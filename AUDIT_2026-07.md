Six parallel audit passes (shared-data core, RFQ/SOW chain, TIC/tenants/apps,
dashboard/AI/notifications, auth/permissions, refactor sweep). Every finding
below was re-grep-verified with file:line evidence before inclusion; items
already tracked in DEAD_CODE_AUDIT.md are not repeated (its backlog was

Legend: ☐ open · ☑ fixed

## P0 — Critical bugs (break a workflow outright)

### ☑ 1. `saveSOW` silently destroys the System Approved state
`housing-modals-sow.js:1562-1653` rebuilds the SOW from form fields and never
copies `system_approved` / `approved_via_rfq` (it preserves only `created_at`,
`progress`, `completed_*`). Any edit-and-save of a system-approved SOW:
- **ED saves** → flags lost, badge silently flips "System Approved" → "ED
  Approved" (approver literally named "System").
- **Non-ED saves** → authority gate strips `edName`/`edDate`, status recomputes
  DOWN to `hm_approved`/`draft` — the SOW re-enters the approval queue while its
  RFQ remains `awarded`. RFQ↔SOW state now inconsistent.
Fix: preserve `system_approved`/`approved_via_rfq`/`edName='System'` from the
existing SOW in saveSOW (same pattern as the `completed_*` preservation).

### ☑ 2. Field-employee worklist can vanish + they can't complete work orders
Two independent bugs that together break the maintenance-crew role:
- `shared-data.js:4453`: the worklist early-exit `total` omits `fieldSowItems`.
  A field employee with work orders but no drafts sees "Nothing requires your
  attention" — their whole queue hidden. Count pill also undercounts.
- `shared-sow.js:43-47`: a duplicate global `canMarkSowComplete()` (mgmt-only,
  plus a dead `r==='hm'` branch) shadows the correct
  `CLFN_PERMS.canMarkSowComplete` (`shared.js:584`, includes `field_employee`;
  unit test asserts it). Wired at `housing-modals-sow.js:1029,1157` +
  `renos.html:1120` — so the crew can't Mark Complete anywhere.
  Also `shared-sow.js:40,51` hardcode `=== ROLE.ED`, dropping super_user.

### ☑ 3. Lease/agreement template PDF broken in production (CSP)
`housing-tic.js:2444` lazy-loads pdf-lib from **unpkg.com**, which is not in
`script-src` (`staticwebapp.config.json:70` allows only cdnjs + jsdelivr) and
not in the SW precache. The `templates/lease-001.pdf` AcroForm path of
`_ticGenerateLeasePdf` always fails ("pdf-lib load failed"). Fix: serve from
cdnjs/jsdelivr (preferred) or add unpkg.com to CSP + sw.js LIB_HOSTS.

## P1 — Bugs (wrong results, confusing state)

### ☑ 4. Collapsed-worklist badge: phantom statuses + drifted count *(2 agents confirmed)*
`housing-init.js:2382` counts SOWs where `approval_status==='pending_hm'/'pending_ed'`
— values that never exist in data (CLAUDE.md-documented footgun) → SOW count
always 0. The whole collapsed count block (2371-2388) also omits drafts and
field work orders, so the pill shows a different number collapsed vs expanded.
Fix: reuse `renderWorklist`'s bucket logic (extract a shared counter).

### ☑ 5. Approved commercial apps leak into Match + "Ready to Match"
`renderMatchView` (`housing-views.js:383-423`) and worklist `matchItems`
(`shared-data.js:4383-4386`) have no `appType==='commercial'` exclusion (the
worklist *Applications* section has one at :4280). Between commercial approval
and building assignment, the app appears in the residential match queue.
Central fix: exclude commercial in `appAssignabilityStatus` (`shared-data.js:2032`)
— covers Match, worklist, saveUnitEdit, saveAddTenant at once.

### ☑ 6. Tenant-note identity fragmentation (merged rows + duplicate minting)
`sbResolveTenantId` (`shared-data.js:875-890`) lacks the `merged_into=is.null`
filter that `_ticResolveTenant` uses, and inserts `{full_name}` only (no
`application_id`/`status`). Consequences: a move-in/work-order/inspection note
can be written to a merged-away tenant row (invisible in the TIC; hero badge
falsely shows "No notes"), and applicant TICs can mint a duplicate row later.
Fix: add `merged_into=is.null` + `order=created_at.asc` to the lookup, carry
`application_id`/`status:'applicant'` on insert where known.

### ☑ 7. AI chat context: `app_type` always undefined
`ai-assistant.js:199` reads `a.app_type || a.type`, but the loaded objects only
have `appType` (mapper `shared-data.js:158`). Every app sent to the AI lacks
its type, so context-answered type questions (On-Rez/transfers, file updates)
can't be answered correctly. Fix: `a.appType || a.app_type`.
(Also `ai-assistant.js:60`: draft mode sends `role: window._effectiveRole || ''`
— `_effectiveRole` is never assigned anywhere; align with :193's
`|| window.currentRole` fallback. Harmless today, JWT overrides.)

### ☑ 8. Message box overlays modals (z-index 100000) and blocks closes on mobile
`#clfn_msgbox` (`shared.css:2164`) out-stacks every modal (max 9999) and is
persistent. Un-dismissed messages sit on top of any modal opened later; on
≤640px the box is full-width and up to 60vh — covering the modal header/×
until the user clears it. Fix: drop z-index below the modal stack (e.g. 1090)
or auto-collapse to a compact pill when a modal opens.

### ☑ 9. Inspection approve: note prompt stacks on the SOW modal + seed drops categories
- `inspections-init.js:563-583`: `_inspPromptSOW` (native confirm → opens SOW
  modal) is not awaited before `promptTenantNote` fires — the note dialog lands
  on top of the SOW form. Chain them like `confirmAssignment` does.
- `inspections-init.js:610`: seeds `category: it.section` with checklist section
  names ('Exterior', 'Bathroom(s)', 'Mechanical'…) that don't match
  `SOW_CATEGORIES` except 'Kitchen' → seeded items land with blank category.
  Add a section→category map.

### ☑ 10. Default milestones were static percentages — spec is a dynamic calc
Resolved per product direction (2026-07-03): "50% Material" = **half the
Materials line of the Price Breakdown** (a materials deposit), then Phase 1/2
at 25% of the contract with Phase 3 = remainder (< $75k), or Phase 1–3 at 20%
with Phase 4 = remainder (>= $75k). Seeded rows carry exact dollars; only the
round-percent phases carry a pct (so `_rfqRefreshMilestonesFromTotal`, which
re-derives gross from pct > 0, can't drift the deposit/remainder rows). Phases
clamp to the remaining contract so a seeded schedule can never exceed the
price. "Reset to default schedule" recomputes from the current breakdown.

### ☑ 11. super_user dropped by static `data-roles` + inline gates
`applyRoleVisibility` (`housing-init.js:2142`) does raw indexOf with no ED-tier
inheritance (unlike renderHeaderNav). Confirmed losses for super_user:
"+ Add Staff" (`housing.html:1055`), "New Tenant" (`housing-init.js:1977`),
RFQs lookup tab (`housing.html:142`), `_rfqCanEdit` (`rfq.js:338`), RFQ unlock
(`rfq.js:418`, also uses effective not real role), `canEditSow`/`canReopenSow`
(`shared-sow.js:40,51`), finance journal approve (`finance-reports.js:613`).
Central fix: teach `applyRoleVisibility` that `ed` implies `super_user`, then
sweep the inline gates.
